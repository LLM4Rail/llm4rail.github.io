大语言模型能在多大程度上帮助求解铁路优化问题？

LLM4Rail 检验这样一个问题：大语言模型与优化求解器、独立验证程序协同工作，能否推进铁路开放基准实例的已知最好界。问题涵盖周期运行图编制、运行图与客流路径一体化优化，以及列车实时调度。

01

研究问题

铁路规划问题难度高、价值大，公开基准又格外完善，很适合用来检验 LLM 能给优化带来什么。

LLM4Rail 研究大语言模型能否帮助改进铁路运行图和调度的可行解、提高下界，以及在已知最优值的实例上复现结果。目录的 166 个模型条目中，87 个有论文或问题库报告的最优结果，2 个的跨来源上下界相等，其余 77 个尚未证明最优。

PESPlib 的 18 个铁路实例和 TimPassLib 的 21 个铁路及城市轨道交通实例均未证明最优。

DISPLIB 的 112 个实例中，72 个见论文最优结果，详见 Stärk 等的表 5–6。另有 nor5_small_1 和 nor5_small_5 的已验证可行解目标值与 Fuchs 等表 B.13 报告的下界相等。其余 38 个尚未证明最优，包括全部 32 个 Wabtec 实例、nor5_small_2 和 nor5_large_1 至 nor5_large_5。

MIPLIB 2017 收录的 15 个铁路模型均在官方解文件第 37 版中标为最优。

LLM4Rail 沿用 LLM4MIP 的研究设计。LLM4MIP 把 LLM 辅助、求解器支撑的工作流用于 MIPLIB 的开放实例；我们把同样的问题带到铁路领域，在这里 LLM 还能利用线路、周期、换乘和股道布置等业务结构。

从一开始我们就承诺两件事：任何结果都不能只凭 LLM 的输出成立；每个公布的结果都写明所用的模型、求解器和算力。

02

问题库

规划涵盖周期运行图编制、客流路径与铁路时隙分配，运营涵盖晚点后的实时调度和运行图重排。

规划18 个实例

PESPlib

周期事件调度问题：找一张按周期重复的运行图，使加权松弛时间最小。目录收录铁路实例 R1L1–R4L4 及两个铁路变体。

  • 收录的 18 个实例均未证明最优。
  • 问题库注明其下界未经验证。
  • 纪录最近一次刷新是在 2026 年 8 月。

规划21 个数据集

TimPassLib

周期运行图与客流路径一体化优化。路网包括汉堡 S-Bahn、雅典地铁、区域及长途铁路，以及加入客流需求的 PESPlib 16 个铁路实例。

  • 收录的 21 个数据集均未证明最优，差距在 0.1% 到 3.1% 之间。
  • Python 验证程序可检查运行图并计算最优客流路径。
在实例目录中查看 21 个数据集 →
运营112 个实例

DISPLIB

列车调度：晚点发生后重新安排列车的径路和次序。真实实例来自西门子交通（意大利）、SINTEF（挪威）、瑞士联邦铁路和 Wabtec。

  • 72 个见论文最优结果，其中 9 个瑞士实例的最优值为 0。另有 2 个实例的跨来源上下界相等。
  • 112 个实例均列出上界和下界，其中 9 个瑞士实例的下界由目标值非负推出。
  • 提供 JSON 格式规范、解验证程序和参考 MILP 求解器。

04

方法

LLM 提出想法，求解器负责计算，独立验证程序决定结果算不算数。

第 1 步

实例

基准文件、当前最好的上下界、官方验证程序，以及线路和车站的业务含义。

第 2 步

LLM 提出假设

理解问题结构，提出分解方式、邻域、约简和下界论证。

第 3 步

后端计算

MIP 求解器和专用算法搜索可行解、计算界，保留完整运行日志。

第 4 步

检查器裁定

问题库自带的验证程序、精确证书重放，以及每个文件的哈希。不通过就回到第 2 步。

采纳规则。LLM4Rail 的实验结果须通过基准的官方验证程序或精确证书检查后才会公布。问题库维护者将结果列入纪录表后，才称为新纪录。

Skill 包

开发中

运行图上界 skill

按线路和通道分解，围绕当前解做邻域重优化，并以已知最好运行图热启动。

开发中

运行图下界 skill

寻找强的环约束和分解方式，输出可在精确算术下重放的下界证书。

计划中

调度 skill

面向 DISPLIB 实例的快速重新排路和排序，并给出下界，说明每个解离最优还有多远。

每个 skill 都会在相同时间和硬件下与两组对照比较：不用该 skill 的同一 LLM 工作流，以及纯求解器。

05

验证与披露

LLM4Rail 的实验结果按下列等级披露证据。实例目录另列公开基线的上下界来源。

  1. E1

    精确证书

    可在有理数算术下重放的界或最优性证明。

  2. E2

    官方验证程序

    通过问题库自带检查程序的解。

  3. E3

    求解器数值结果

    求解器在默认容差下报告的界。

  4. E4

    容差内接受

    只在注明的数值容差下成立的结果。

LLM4Rail 实验结果的披露内容

  • 所用的 LLM 及版本
  • 求解器名称及版本
  • 每个实例的耗时和硬件
  • 每个实例消耗的 token 数
  • 模型文件和解文件的 SHA-256
  • 对比的基准及其日期
